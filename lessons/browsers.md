# Browsers

- Chrome (owner, 14 Nov 2026: Google sync needs Chrome, not Chromium): AUR `google-chrome`. Its build script only unpacks Google's .deb from dl.google.com; its SHA256 matched Google's own index (`https://dl.google.com/linux/chrome/deb/dists/stable/main/binary-amd64/Packages`). The package holds one setuid file, `opt/google/chrome/chrome-sandbox`, as normal, and two menu entries: `google-chrome.desktop` and `com.google.Chrome.desktop`.
- Update Chrome: `kiln-watch` says when Google or the AUR has a newer one. Then `git pull` in ~/.cache/kiln-aur/google-chrome, reviewer reads the diff, `makepkg`, `sudo pacman -U`, and remove `pkg/` and `src/` (makepkg leaves an owner-setuid copy of chrome-sandbox there, which the sentry rightly flags).
- Chrome on the WX 3200, never the 4090: `/usr/local/bin/google-chrome-stable` (config/chrome/) sets Mesa-only EGL and GLX, the Radeon Vulkan driver and radeonsi VA-API, then starts the package's launcher. Both menu entries are copied to ~/.local/share/applications pointing there. Checked 14 Nov: the GPU process holds only renderD128 (the WX 3200) and libEGL_mesa, and nvidia-smi lists no Chrome. Not covered: web apps installed from Chrome start /opt/google/chrome/google-chrome directly.
- Flags in ~/.config/chrome-flags.conf: `--ozone-platform=wayland`, `--enable-features=AcceleratedVideoEncoder`. VA-API decode is on by default in Chrome 157.
- The WX 3200 (Polaris 12) decodes MPEG-2, VC-1, H.264, HEVC and HEVC 10-bit, and encodes H.264 and HEVC. No VP9 or AV1: most YouTube decodes on the CPU.
- Both browsers use the system's DNS by policy (`/etc/firefox/policies/policies.json`, `/etc/opt/chrome/policies/managed/kiln-dns.json`), so the router's blocking applies. Chrome shows "Managed by your organisation" because of it.
- Hyprland 0.57 with Lua: start a program from a script with `hyprctl dispatch 'hl.dsp.exec_cmd("...")'`. Claude's shell cannot write its scratchpad from programs started that way; use a path in the home folder.
- A program started with `hl.dsp.exec_cmd` while the Claude pull-down is showing opens on the pull-down's workspace (special:sidekick) and vanishes with it. Move it: `hyprctl dispatch 'hl.dsp.window.move({ workspace = "1", window = "address:0x<address>" })'`; the address is in `hyprctl clients`.
- Claude in Chrome needs no Claude Desktop: it is a Chrome Web Store extension, signed in with a paid claude.ai plan (support.claude.com article 12012173). Desktop is only for Desktop-driven tasks.
- Claude Desktop (owner asked, 14 Nov 2026): `claude-desktop` from the cachyos repository, 5.11492.0-1. CachyOS's package unpacks Anthropic's official Debian .deb, unpatched. Anthropic's Linux build is a beta for Debian and Ubuntu; on Arch it is unsupported by Anthropic. It updates with the system. It brought in QEMU and OVMF for Cowork, which also needs the owner in the `kvm` group and `vhost_vsock`: not set up.

# Desktop

Hyprland, graphics and the screen.

- CachyOS, 13 Nov 2026: Hyprland's config is CachyOS's Lua files in `~/.config/hypr/config/`. Kiln's own settings go in `config/kiln.lua`, loaded last. Mouse copy and paste are there.
- CachyOS, 13 Nov 2026: the Philips 49M2C8900L reports 3840x1080@60 as its preferred mode, so `mode = "preferred"` gives the wrong one. `config/monitors.lua` names `5120x1440@120` with `vrr = 1`. The screen is `DP-4` on the WX 3200 (`card1`).
- CachyOS, 13 Nov 2026: no gaps, square corners and the `lua:kiln` layout are in `config/kiln.lua`. 1 to 4 windows make equal columns; from 5, 4 columns with the extra windows stacked from the right. Tested with 1 to 9 windows on workspace 9: every pixel is used.
- CachyOS, 13 Nov 2026: the wallpaper is drawn by Noctalia, CachyOS's shell, whose settings are `~/.config/noctalia/config.toml`. `[wallpaper] enabled = false` turns it off; Hyprland's `misc.background_color` then shows. Noctalia takes its colours from the wallpaper by default, so set `[theme] source = "builtin"` first. `noctalia config validate` checks the file, `noctalia config export full` shows every setting, and Noctalia reloads the file by itself. `hyprctl layers` shows whether anything is drawn on the background layer.
- CachyOS, 13 Nov 2026: Noctalia's weather needs `[location]` in its config: `auto_locate = true`, or `address = "<town>"`. Location comes from `api.noctalia.dev`, weather from Open-Meteo. The results land in `~/.cache/noctalia/location.json` and `weather.json`. Auto-locate gave only "United Kingdom", with central London's coordinates.
- CachyOS, 13 Nov 2026: the middle mouse button opens and hides Claude Code in a pull-down window (`kiln-sidekick`, rules in `config/kiln.lua`). It takes over middle-click everywhere, so pasting with middle-click and opening links in new tabs with it stop working. Its class `kiln-sidekick` must be in the clipboard code's terminal list, or the copy button sends a plain Ctrl+C, which interrupts Claude.
- Programs started from Hyprland get its PATH, which lacks `~/.local/bin`, where Claude Code lives. Use the full path, `$HOME/.local/bin/claude`. The first pull-down only flashed, as `claude` was not found and the window closed at once. Test a key's command with the desktop's PATH: `env -i HOME=/home/indy PATH=/usr/local/sbin:/usr/local/bin:/usr/bin <command>`.
- CachyOS, 13 Nov 2026: the Omarchy look is in `config/kiln.lua` (copy in the repo's `config/hypr/kiln.lua`): Tokyo Night borders, solid windows, no blur or shadow, Omarchy's animations. CachyOS's keys are kept. Noctalia's built-in `Tokyo-Night` scheme colours the bar, kitty, GTK and Qt to match. `config/hypr/hyprland.lua` in the repo is v1's Gentoo file, kept for reference.
- The screen is on mini DisplayPort from the WX 3200, which has only mini DisplayPort sockets. HDMI into the RTX 4090 is the fallback if a live image shows a black screen.
- Kiln needs a login screen that reaches graphical.target, for a fair boot comparison with Ubuntu.
- Card numbers and connector names change. Ubuntu called the screen `card2-DP-7`, and the live system `card0-DP-4`, on the same WX 3200. Choose the card by PCI address 02:00.0.
- The firmware starts on the WX 3200. The screen runs 5120x1440 at 120 Hz through it.
- The RTX 4090 runs at x8, not x16, with both cards fitted. The owner decided this does not matter, as the card is mainly for ML work.
- Hyprland 0.57 reads only Lua config, in `~/.config/hypr/hyprland.lua`, and needs Lua 5.5. Gentoo stops at 5.4. Check a config with `Hyprland --verify-config --config <file>`. It works in a chroot.
- Gentoo still masks the Hyprland names after moving them out of its main repo, so a separate repo needs `package.unmask` lines ending in `::kiln`.
- In Hyprland 0.57, `hyprctl dispatch` takes Lua, such as `hyprctl dispatch 'hl.dsp.workspace.toggle_special("sidekick")'`. A window with the rule `workspace = "special:sidekick"` opens with that workspace showing.
- Mouse copy and paste: `hl.bind` takes a Lua function, and `hl.dsp.send_shortcut({ mods, key })` works with `hl.dispatch`. Check `hl.get_active_window().class`, and send Ctrl+Shift in a terminal, because Ctrl+C there stops what is running. Forward is `mouse:276`, back is `mouse:275`, middle is `mouse:274`. Hyprland's Lua definitions are in `/usr/share/hypr/stubs/hl.meta.lua`.
- Omarchy 4.0 writes its Hyprland settings in Lua, in `default/hypr/`, so they run on Hyprland 0.57 here. Most of its bindings call `omarchy-*` scripts or its Quickshell shell, so those cannot be copied alone. `send_shortcut` can leave a key stuck, so Omarchy sends `send_key_state` down, then up 50 ms later.
- Custom window layout: write it with `hl.layout.register("kiln", { recalculate = ... })`, and set `general.layout = "lua:kiln"`. The `lua:` prefix is needed. Without it Hyprland falls back to dwindle with no error, and `getoption` still shows the name. Test by opening windows on an empty workspace, as `hl.dsp.exec_cmd("foot", { workspace = "9 silent" })`, and reading `hyprctl -j clients`.
- The shortcuts on the desktop are one image, shown by `swaybg`. After changing a key, edit and run `config/desktop/make-shortcuts.py`, then copy the image to `~/.local/share/kiln/`.
- Turning the screen off in Hyprland 0.57: `hyprctl dispatch 'hl.dsp.dpms({ action = "disable" })'`, and `"enable"` to turn it on. `kiln-idle` uses this with `swayidle`.
- On `7.3.1-gentoo-kiln-gcc` the pointer did not show, though the mouse worked and Hyprland's log showed no error. `cursor.no_hardware_cursors = 1` fixed it. Whether the kernel or the first full restart with the Omarchy settings caused it is not yet known.
- `AQ_DRM_DEVICES` is split by colons, so it cannot take a by-path card name, which has colons in it. `kiln-session` resolves the name to `/dev/dri/cardN` first.
- GPU monitoring in btop: the RTX 4090 works through `libnvidia-ml`, which comes with the NVIDIA driver. For the WX 3200, btop suggests `dev-util/rocm-smi`, but that package is testing-only (`~amd64`) with no ready-built version, and ROCm 6 and 7 no longer support Polaris chips like the WX 3200. The owner chose to skip it.
- Hyprland 0.57 warns at start when `hyprland-guiutils` is missing. It holds Hyprland's pop-up dialogs, such as "not responding". Kiln has no recipe for it or for `hyprtoolkit`, which it needs, so `misc.disable_hyprland_guiutils_check` turns the warning off, by owner's choice on 13 Nov 2026. A recipe would bring the dialogs back.

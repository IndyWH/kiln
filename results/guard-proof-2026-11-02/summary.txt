Kiln disk guard: proof, 2 Nov 2026, mlrig, Gentoo LiveGUI

STATUS: step 3 complete. Every disk except the Crucial is locked. The hook is
live. Proved on the live system only: the guard must be installed and proved
again on the installed system, which uses systemd.

Hook rules (hook-tests.log): 18 tests, all passed
  115 commands that must be blocked, 65 that must be allowed.
  They are only read as text, on made-up disks. None is ever run.

Kernel lock (fake-disks.log): 35 checks, all passed. Run twice, same result.
  - Fake disks accept writes before the lock, so the test can see a write.
  - Locking opens the device read-only and sends no write.
  - After the lock, dd, direct writes, blkdiscard, mkfs, wipefs, sgdisk and a
    read-write mount were all refused, and the data was unchanged.
  - A new fake disk locked itself when it appeared, using the real udev rule
    with one added line that limits it to fake disks.

Real disks, after install (install.log, real-status.txt, real-after.txt):
  - The kernel flag is set on every disk and partition except the Crucial.
  - No write reached any disk. All other disks show 0 writes and 0 sectors.
    The Crucial still shows the same 3 writes as before the first test: empty
    cache flushes, with 0 sectors of data.
  - The installed guard files match the repo, and are owned by root.

Hook, live in Claude Code after a restart:
  Blocked  dd, zero bytes, aimed at a real Samsung
  Blocked  dd, zero bytes, aimed at a real SATA disk
  Blocked  Write tool, aimed at the guard's own folder
  Blocked  sudo running the fake-disk test script (it names raw devices)
  Allowed  dd, zero bytes, to /dev/null
  Allowed  read-only status and disk checks
  The zero-byte commands would have written nothing even if the hook had failed.

Earlier runs that failed, each one a fault in the test, not in the lock:
  1. A test write damaged the fake disk's partition table, and dd then made a
     plain file in /dev, in memory. Removed. Writes now avoid the table.
  2. sgdisk exits 0 even when the kernel refuses its writes. It is now judged
     by the kernel's answers and the data.
  3. A fake disk's lock flag carried over to the next run. Now cleared.

Not tested live: the hook failing outright, such as a crash on start. Its own
errors are tested to end in a block, and onFailure is set to block, as the
Claude Code docs describe.

Installed udev rule (installed-rule.log), run by the owner in a terminal: 32
checks, all passed. A new fake disk was locked as soon as it appeared, using the
rule as installed, and refused dd, direct writes and mkfs. Real disks' write
counts and lock flags did not change.
